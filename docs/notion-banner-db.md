# 홈 배너 노션 DB 스키마 (개발자용)

메인 화면 상단 슬라이드 배너를 노션에서 관리하기 위한 설계 문서.
연결(Connection) 만들기 · 토큰 발급 · 데이터 소스 개념은
[notion-guide-db.md](./notion-guide-db.md)의 「노션 셋업 절차」와 동일하므로
여기서는 배너 DB에만 해당하는 내용을 적는다.
운영진용 사용법은 [banner-admin-manual.md](./banner-admin-manual.md) 참고.

- DB URL: `https://app.notion.com/p/3b48b57d7cf480aca050fdc06b4d7c77?v=…`
- 코드: `lib/notion.ts`의 `getBanners()` → `lib/content.ts`의 `getBanners()`
  → `app/page.tsx` → `components/BannerSlider.tsx`

## DB 속성 정의

| 속성명 | 타입 | 용도 |
|---|---|---|
| `이미지` | 파일과 미디어(Files & media) | 배너 배경. 첫 번째 파일만 쓴다 |
| `배경색` | 텍스트(Text) | **이미지가 없을 때** 대신 깔 배경색 |
| `링크` | URL | 배너를 눌렀을 때 이동할 주소 |
| `타이틀` | 텍스트(Text) | 배경 위에 겹쳐 쓰는 큰 글씨 |
| `설명` | 텍스트(Text) | 타이틀 아래 작은 글씨 |
| `이름` | 제목(Title) | 노션에서 행을 알아보기 위한 이름. 화면에는 안 나온다 |
| `순서` | 숫자(Number) | *(선택)* 만들면 이 값으로 정렬한다. 작은 수가 앞 |

**배경(`이미지` 또는 `배경색`)이 둘 다 없는 행은 화면에 나오지 않는다.**
배경 없는 배너는 성립하지 않을뿐더러, 노션이 기본으로 만들어 두는 빈 행이 이
규칙에 함께 걸러진다. 바꿔 말해 **행을 지우지 않고 둘 다 비워 두면 임시로 내릴 수 있다.**

`타이틀`·`설명`이 둘 다 비면 글씨 없이 배경만 나온다 — 문구가 이미 박혀 있는
배너 이미지는 이렇게 쓰면 된다. 제목 열(`이름`)은 화면에 쓰지 않는다.
운영진이 노션 목록에서 행을 구분할 이름과, 배너에 실제로 찍히는 문구는 다른
것이어야 하기 때문이다(문구 없는 배너에도 이름은 필요하다).

`링크`가 외부 주소면 새 탭, `/guide/streaming` 처럼 슬래시로 시작하면 사이트 안에서
이동한다. 비우면 클릭되지 않는 배너가 된다. `https://`를 빠뜨리고 `tinyurl.com/xxxx`
로만 적어도 코드가 붙여 준다 — 판단·보정 규칙은 사이트 공용(`lib/url.ts`의
`resolveHref()`)이고, 표는 [notion-links-db.md](./notion-links-db.md)에 있다.

### `배경색`

이미지를 아직 못 구했을 때 색만으로 배너를 띄우기 위한 칸이다.
**`이미지`가 있으면 무시된다** — 배경은 하나뿐이고, 이미지가 있는데 색을 쓸 이유가 없다.

적는 형태는 아래를 모두 받는다. 알아볼 수 없는 값은 무시하고 기본 하늘색을 깐다.

```
#00BFFF   00BFFF   #0bf   skyblue   rgb(0, 191, 255)
```

**글자색은 배경색 밝기에 따라 자동으로 흰색 / 남색이 된다.** (WCAG 상대 휘도 기준)
운영진이 밝은 색을 골랐을 때 흰 글씨가 사라지는 사고를 막기 위한 것으로,
글자색을 지정하는 칸은 따로 두지 않는다.

## 순서

`순서` 숫자 열이 있으면 그 값(작은 수가 앞), 없으면 **노션에 행을 추가한 순서**다.
배너가 많아야 대여섯 장이라 만든 순서로도 대개 충분하지만, 차례를 직접 쥐고 싶으면
열을 만들면 된다 — 가이드 · 바로가기와 같은 규칙이다.

> ⚠ **행을 끌어서 옮기거나 DB 뷰에 정렬을 걸어도 화면 순서는 바뀌지 않는다.**
> 노션 API 가 뷰의 수동 정렬을 노출하지 않기 때문이다. 예전 이 문서에는 「보이는
> 행 순서 그대로 온다」고 적혀 있었는데 사실이 아니었다 — `sorts` 를 생략하면
> `created_time` **내림차순**(최근에 만든 배너가 맨 앞)이 되어 화면이 노션과 반대로
> 나왔다. 지금은 `lib/notion.ts` 의 `queryRows()` 가 오름차순을 명시한다.
>
> 순서를 직접 쥐어야 하면 **`순서` 숫자 열을 만들고 1, 2, 3… 을 넣으면 된다** —
> 가이드 · 바로가기와 같은 규칙이고, 코드는 이미 그 열을 보고 있다(없으면 무시).
> 값을 비워 둔 행은 맨 뒤로 간다.

## 이미지 서빙

가이드와 같은 방식이다 — 노션의 S3 서명 URL은 1시간 뒤 403이 되므로 클라이언트에
내보내지 않고 `/api/banner-image?p=<pageId>&i=0&v=<버전 토큰>` 프록시로 중계한다.
`v`는 이미지가 실제로 교체될 때만 바뀌므로 응답을 사실상 영구 캐시한다.
자세한 근거는 `lib/notion-image.ts` 주석 참고.

**프록시를 가이드용과 배너용으로 나눠 둔 이유**는 각 라우트가 자기 데이터 소스에
속한 페이지인지 검사해서, 토큰이 읽을 수 있는 아무 페이지의 첨부파일이나 꺼내주는
창구가 되지 않게 하기 위해서다. 한 라우트로 합치면 "어느 DB냐"를 요청자가 고르게 된다.

권장 이미지 비율은 **16:9**(모바일) ~ **21:9**(데스크톱). 슬라이더가 `object-cover`로
채우므로 위아래가 잘릴 수 있다. 중요한 문구는 가운데에 두는 편이 안전하다.

## 환경변수

```sh
NOTION_TOKEN=ntn_xxxxxxxxxxxxxxxxxxxx        # 가이드 DB와 같은 토큰
NOTION_BANNER_DB_ID=3b48b57d7cf480aca050fdc06b4d7c77
NOTION_BANNER_DS_ID=3b48b57d-7cf4-803c-b0f9-000b1c928123   # 선택: 요청당 왕복 한 번을 아낀다
```

배너 DB 페이지에서 `⋯` → **연결(Connections)** → 가이드와 같은 연결을 붙여야 한다.
**이 단계를 빠뜨리면 API가 404를 반환하고** 홈 배너 영역이 통째로 비어 보인다
(서버 로그에 `[banners] 노션 조회 실패` 가 찍힌다).

> **DB → 데이터 소스 조회에는 fetch 캐시를 걸지 않는다.** Next의 fetch 캐시는
> 실패 응답도 그대로 담아 두기 때문에, 연결을 붙이기 전에 404가 한 번 나면
> 노션에서 연결을 붙인 뒤에도 캐시 기간(한 시간) 내내 404를 다시 꺼내 쓴다.
> "노션은 고쳤는데 화면이 안 돌아오는" 상황이 되므로, 이 조회만 `no-store`로 두고
> 왕복은 프로세스 메모리 캐시(`lib/notion.ts`의 `dataSourceCache`)로 줄인다.
