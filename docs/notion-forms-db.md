# 폼 · 헬퍼 노션 DB 스키마 (개발자 · 운영진용)

`/forms`(폼 바로가기) · `/helper`(헬퍼 신청하기) 두 페이지에 뿌릴 **폼 목록**을
노션에서 관리하기 위한 문서. 연결(Connection) 만들기 · 토큰 발급 · 데이터 소스
개념은 [notion-guide-db.md](./notion-guide-db.md)의 「노션 셋업 절차」와 같으므로
여기서는 이 DB에만 해당하는 내용을 적는다.

- 코드: `lib/notion.ts`의 `getFormLinks()` → `lib/content.ts`의 `getFormLinks()`
  → `app/forms/page.tsx` · `app/helper/page.tsx` → `components/FormLinks.tsx`
- 홈 바로가기 버튼(`폼 바로가기` · `헬퍼 신청하기`)의 `URL` 은 각각 `/forms` ·
  `/helper` 로 적는다 ([notion-links-db.md](./notion-links-db.md)).

## 왜 새 DB 인가 (바로가기 DB 를 같이 쓰지 않는 이유)

바로가기 DB(`main links`)는 **홈 아이콘 한 줄**을 만드는 곳이다. 거기 있는 행은
전부 홈 화면에 아이콘으로 나가므로, 폼을 그 DB 에 넣으면 폼이 늘어날 때마다 홈
아이콘이 같이 늘어난다. 「어떤 행은 홈에 나가고 어떤 행은 안 나간다」를 열 하나로
구분하기 시작하면, 운영진이 실수하기 쉬운 DB 가 된다.

폼 목록에는 아이콘 버튼에 없는 값(설명 · 접수 기간 · 마감 여부)도 필요하다.
그래서 **폼 전용 DB 를 하나 새로 만들고, 폼과 헬퍼는 그 안에서 `구분` 열로 나눈다.**
폼과 헬퍼는 운영 방식이 같아서(폼 링크 하나 + 기간 + 마감) 열이 똑같은데, DB 를
둘로 나누면 연결 · 환경변수 · 문서가 두 벌이 되기만 한다.

## DB 속성 정의

| 속성명 | 타입 | 용도 |
|---|---|---|
| (제목 열) | 제목(Title) | 폼 이름. **열 이름은 아무거나 좋다** (`이름` · `Name` · `폼 이름`) |
| `구분` | 선택(Select) | `폼` 또는 `헬퍼` — 어느 페이지에 나올지 |
| `설명` | 텍스트(Rich text) | 이름 아래 한 줄 설명 |
| `URL` | URL | 구글폼 등 실제 신청 주소 |
| `상태` | 선택(Select) | `진행중` · `마감` · `예정` (비면 진행중) |
| `기간` | 텍스트(Rich text) | 화면에 그대로 나오는 접수 기간 (`~ 8/24 23:59`) |
| `emoji` | 텍스트(Rich text) | 카드 왼쪽 이모지. 비면 폼 📝 · 헬퍼 🙋 |
| `순서` | 숫자(Number) | 화면에 나오는 차례. 작은 수가 앞 |

제목 열은 이름이 아니라 **타입**으로 찾는다(`lib/notion.ts`의 `titleOf()`).
노션이 만들어 주는 기본 제목 열 이름이 UI 언어에 따라 `이름` · `Name` 으로 갈리고,
운영진이 고쳐 쓰기도 해서 이름을 맞추라고 하면 목록이 통째로 비는 사고가 난다.

### `구분` — 이 열이 비면 화면에 안 나온다

`폼` · `헬퍼` 둘 중 하나여야 한다(영문 `form` · `helper` 도 받는다). 비어 있거나
다른 값이면 어느 페이지에도 나오지 않는다 — 노션이 기본으로 만들어 두는 빈 행이
여기서 함께 걸러진다.

### `상태` · `URL` — 링크가 열리는 조건

| 상태 | URL | 화면 |
|---|---|---|
| `진행중` (또는 비움) | 있음 | 카드 전체가 링크. 「신청하러 가기 ›」 |
| `진행중` (또는 비움) | 비움 | **준비 중** 뱃지, 누를 수 없음 |
| `마감` · `종료` | 있든 없든 | **마감** 뱃지, 누를 수 없음 (회색) |
| `예정` · `오픈예정` · `준비중` | — | **준비 중** 뱃지, 누를 수 없음 |

마감된 폼도 목록에 남긴다. 「이 폼은 끝났다」를 보여주는 편이 「사라져서 못
찾겠다」보다 낫기 때문이다. 완전히 감추려면 행을 지우거나 `구분` 을 비운다.

`URL` 이 사이트 안 · 밖을 자동으로 가르는 규칙은 다른 DB 와 같다
(`lib/url.ts`의 `resolveHref()` → `<SmartLink>`). `https://` 를 빠뜨려도 코드가
붙여 준다.

## 순서

`순서` 숫자 열이 있으면 그 값, 없거나 비면 **노션에 행을 추가한 순서**(먼저 만든
것이 앞). 값을 비워 둔 행은 맨 뒤로 간다.

> **노션에서 줄을 드래그해도 사이트 순서는 바뀌지 않는다.** 노션 API 가 뷰의 수동
> 정렬을 알려주지 않기 때문이다 — 자세한 내용은 [notion-links-db.md](./notion-links-db.md)
> 의 「순서」 절과 `lib/notion.ts`의 `queryRows()` 주석 참고.

점검은 `node scripts/notion-check.mjs`.

## 만드는 순서 (한 번만)

1. 노션에서 새 DB 를 만든다(인라인이어도 된다). 위 표대로 열을 만든다 —
   `구분` · `URL` 만 있으면 화면은 뜨고, 나머지는 있으면 쓰고 없으면 무시한다.
2. 그 DB(또는 DB 가 들어 있는 페이지)에 기존 통합의 **연결(Connection)** 을 붙인다.
   권한은 위에서 아래로만 흐르므로, 노출 범위를 좁게 두려면 DB 쪽에 붙이는 편이 낫다.
3. DB 주소에서 ID 를 꺼내 `.env` 에 넣는다(아래). `NOTION_TOKEN` 은 가이드 · 배너 ·
   스밍리스트와 **같은 토큰**이다.
4. `node scripts/notion-check.mjs` 로 연결 · 열 이름 · 순서를 확인한다.
   `NOTION_FORMS_DS_ID` 를 아직 안 넣었다면 스크립트가 넣을 값을 알려준다.
5. 마지막으로 바로가기 DB(`main links`)에서 `폼 바로가기` · `헬퍼 신청하기` 행의
   `URL` 을 `/forms` · `/helper` 로 바꾼다. **이 단계를 맨 뒤에 두는 이유**: 폼을
   하나도 안 채운 상태에서 먼저 바꾸면, 홈에서 눌러 들어온 사람이 빈 페이지를 본다.

## 환경변수

```sh
NOTION_TOKEN=ntn_xxxxxxxxxxxxxxxxxxxx   # 가이드 · 배너 · 스밍리스트 · 바로가기와 같은 토큰
NOTION_FORMS_DB_ID=<DB 주소의 32자리 ID>
NOTION_FORMS_DS_ID=<선택: 요청당 왕복 한 번을 아낀다 — notion-check 가 알려준다>
```

**환경변수가 없어도 사이트는 정상 동작한다.** 조회가 실패하면 목록만 비고
(`[form-links] 노션 조회 실패` 로그), 페이지는 「진행 중인 폼이 없어요」 안내를
보여준다. 가이드 · 배너와 같은 방침이다 — 한 DB 의 문제로 페이지가 500 이 되지
않게 한다.

반영 주기는 ISR 300초 (`app/forms/page.tsx` · `app/helper/page.tsx`의 `revalidate`).
