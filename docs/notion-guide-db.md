# 가이드 노션 DB 스키마 (개발자용)

가이드 이미지·목록을 노션 데이터베이스에서 관리하기 위한 설계 문서.
운영진용 사용법은 [guide-admin-manual.md](./guide-admin-manual.md) 참고.

## 설계 원칙

1. **코드는 개별 가이드를 하드코딩하지 않는다.**
   코드가 아는 것은 DB ID 하나뿐이고, 행(row)은 전부 조회 결과로만 다룬다.
   따라서 운영진이 행을 추가·삭제·수정해도 코드는 손대지 않는다.

2. **운영진이 지켜야 할 규칙을 만들지 않는다.**
   파일명 규칙·확장자 규칙·업로드 순서 같은 약속은 언젠가 반드시 깨진다.
   이미지는 파일명이 무엇이든, 몇 번을 지우고 다시 올리든 동작해야 한다.

3. **이미지 주소에 버전 토큰을 붙인다.**
   `/api/guide-image?page=<pageId>&i=<n>&v=<hash>` 형태로 서빙한다.
   `v`는 노션 파일 객체 경로에서 파생되므로 **이미지가 실제로 바뀔 때만** 변한다.
   - 이미지가 바뀌면 → URL이 바뀜 → 캐시 우회 → 즉시 새 이미지
   - 이미지가 그대로면 → URL 동일 → 캐시 적중 → 원본 재조회 없음

   덕분에 캐시를 길게 잡으면서도 갱신은 즉시 반영된다.

4. **서명 URL을 클라이언트에 노출하지 않는다.**
   노션이 내려주는 S3 URL은 `X-Amz-Expires=3600`, 즉 1시간 뒤 403이 된다.
   HTML에 박히면 캐시된 페이지의 이미지가 통째로 깨지므로,
   서버 프록시가 요청 시점에 새 서명 URL을 받아 바이트만 중계한다.

## DB 속성 정의

데이터베이스 이름: **가이드** (이름은 자유, 코드는 ID로 참조)

| 속성명 | 타입 | 필수 | 용도 |
|---|---|:--:|---|
| `제목` | 제목(Title) | ✅ | 카드에 표시될 이름. 예) `멜론` |
| `섹션` | 선택(Select) | ✅ | 어느 페이지의 어느 묶음에 들어갈지. 아래 8개 고정 |
| `상태` | 선택(Select) | ✅ | `공개` / `오픈예정` |
| `이미지` | 파일과 미디어(Files & media) | | 가이드 이미지. 여러 장이면 순서대로 표시 |
| `설명` | 텍스트(Text) | | 카드 부제. 비워도 됨 |
| `플랫폼` | 다중 선택(Multi-select) | | 플랫폼 아이콘. 아래 12개 |
| `순서` | 숫자(Number) | | 섹션 안에서의 정렬. 비우면 맨 뒤 |

`상태` 기본값은 **오픈예정**으로 두는 것을 권장한다.
행을 만들자마자 미완성 가이드가 사이트에 노출되는 사고를 막는다.

**행 식별자는 노션 page ID를 그대로 쓴다.** `GuideItem.slug`에는 page ID가 들어간다.
운영진이 입력할 식별자 칸을 따로 두지 않는 이유는 아래 「slug를 두지 않는 이유」 참고.

### `섹션` 선택지 (8개 고정) → 코드 매핑

| 노션 선택지 | 노출 페이지 | 코드상 section id | 섹션 표시명 |
|---|---|---|---|
| `음원 스트리밍` | `/guide/streaming` | `audio` | 음원 스트리밍 |
| `MV 스트리밍` | `/guide/streaming` | `mv` | MV 스트리밍 |
| `아이디 생성` | `/guide/id-generate` | `id-generate` | 아이디 생성 |
| `음악방송 투표` | `/guide/voting` | `music-show` | 음악방송 투표 |
| `시상식 투표` | `/guide/voting` | `awards` | 시상식 투표 |
| `음원 다운로드` | `/guide/download` | `audio-dl` | 음원 다운로드 |
| `MV 다운로드` | `/guide/download` | `mv-dl` | MV 다운로드 |
| `기타 가이드` | `/guide/etc` | `etc` | 기타 가이드 |

선택지를 한 속성에 몰아넣은 이유: 「페이지」와 「섹션」을 따로 두면
`페이지=투표` + `섹션=MV 다운로드` 같은 불가능한 조합을 운영진이 만들 수 있다.
하나로 합치면 드롭다운에서 고르는 것 외에 선택지가 없다.

**섹션을 새로 추가하려면 코드 수정이 필요하다.** 섹션의 표시 순서와 id를
코드가 정하기 때문이다. 가이드 항목 추가는 코드 수정이 필요 없다.

> **`스트리밍 도구` 섹션은 뺐다.** 기존 `lib/content.ts`에는 `tools` 섹션에
> Station Head · Sound assistant · 삼성 뮤직 · Music wave가 묶여 있었으나,
> 이것들도 결국 스트리밍 가이드이므로 별도 섹션으로 나눌 이유가 없다.
> 해당 가이드들은 `음원 스트리밍`에 함께 넣는다.
>
> 관련 이미지(`Station Head 가이드 …` 2장, `…동시재생가이드…` 2장,
> `삼성뮤직활용가이드…` 1장)도 `음원 스트리밍` 행으로 올린다.

### `플랫폼` 선택지 (15개)

`lib/platform-icons.ts`의 `PLATFORM_ICONS` 값과 1:1로 맞춘다.
노션에는 한글 표시명을 옵션으로 두고, 코드가 역매핑해서 아이콘 키를 얻는다.

```
멜론 · 지니 · 벅스 · 플로 · 바이브 · 스포티파이 · 애플뮤직 · 카카오뮤직
아이돌챔프 · 엠넷플러스 · 팬캐스트 · 뮤빗 · 뮤니버스 · 링크 · 하이어
```

**아이콘 파일이 없는 플랫폼은 `PLATFORM_ICONS`에 넣지 않는다.**
키가 등록돼 있으면 `PlatformIcon`이 `/icons/<key>.png`를 무조건 요청하므로,
파일이 없으면 404 로 깨진 이미지가 그려진다. 등록하지 않으면 그 값은 조용히
무시되고 아이콘 자리만 비므로, 파일이 준비될 때까지는 이쪽이 낫다.

노션 옵션에만 있고 코드에 없는 값도 같은 이유로 무해하다 — 점검 스크립트가
경고만 띄우고 넘어간다.

추가 절차: `public/icons/<key>.png` (480×480 권장) → `PLATFORM_ICONS`에 한 줄
→ 노션 `플랫폼` 선택지에 한글 표시명 추가.

### slug를 두지 않는 이유

초안에는 `slug` 텍스트 속성이 있었으나 뺐다.

`GuideItem.slug`의 현재 유일한 쓰임은 `GuideList.tsx`의 React `key`이고,
여기에는 노션 page ID가 그대로 들어가면 충분하다. 운영진이 채울 이유가 없다.

사람이 읽는 고정 앵커(`/guide/streaming#melon`)가 필요해지는 경우는 있다.
`schedules.guide_url`에서 특정 가이드로 딥링크를 걸고 싶을 때다. 다만
현재 `GuideList`는 카드에 `id` 속성을 달지 않아 앵커 자체가 동작하지 않는다.
앵커 기능을 만들 때 속성을 추가해도 늦지 않으므로, 그때까지는 운영진이 보는
빈 칸을 하나라도 줄인다. **"비워두세요"라고 적힌 칸은 언젠가 채워진다.**

## 노션 셋업 절차

### 0. 어떤 인증 방식을 쓰나 — 내부 연결(Internal)

노션은 2026년 5월 개편으로 용어가 **integration → connection(연결)**으로 바뀌었고,
인증 방식이 세 가지다. 이 프로젝트는 **내부 연결(Internal connection)**을 쓴다.

| 방식 | 무엇 | 이 프로젝트에 |
|---|---|---|
| **내부 연결 + 액세스 토큰** | 워크스페이스 하나에 고정된 정적 토큰 | ✅ **이걸 쓴다** |
| 공개 연결 + OAuth | 남의 워크스페이스에 앱을 배포할 때 | ❌ 불필요 |
| 개인 액세스 토큰(PAT) | 특정 **사람** 계정에 묶인 토큰 | ❌ 쓰면 안 됨 |

**OAuth를 쓰지 않는 이유** — OAuth는 여러 워크스페이스의 사용자가 각자 우리 앱을
설치하는 상황을 위한 것이다. 우리는 워크스페이스 하나에서 서버가 읽기만 하므로,
OAuth를 쓰면 토큰 갱신(refresh) 처리만 늘고 얻는 게 없다.

**PAT을 쓰지 않는 이유** — PAT은 발급한 *사람*의 권한에 묶인다. 그 사람이 팀을
떠나거나 계정이 정리되면 사이트의 가이드가 통째로 죽는다. 내부 연결은 사람이 아니라
**워크스페이스**에 묶이므로 담당자가 바뀌어도 살아남는다. 운영진이 도는 팬사이트에서는
이 차이가 결정적이다.

### 1. 내부 연결 생성

개발자 포털 주소가 바뀌었다. 예전 `notion.so/profile/integrations`가 아니다.

1. https://app.notion.com/developers 접속
   (또는 노션에서 `설정` → `연결` → 맨 아래 **직접 연결 만들기**)
2. **+ 새 연결(New connection)** → 이름 입력(예: `drstrm-web`), 연결할 워크스페이스 선택
3. 권한(Capabilities)은 **콘텐츠 읽기(Read content)만** 체크 — 쓰기 권한은 필요 없다
4. `설정` → `연결`에서 만든 연결 옆 `•••` → **내부 연결 토큰 조회**로 토큰 복사

2026년 5월부터 **워크스페이스 소유자가 아니어도 멤버면 연결을 만들 수 있다.**
예전에 소유자 권한이 없어 막혔다면 지금은 된다.

### 2. DB에 연결 붙이기

만든 가이드 DB 페이지에서 우측 상단 `⋯` → **연결(Connections)** → 위에서 만든
연결 선택. **이 단계를 빠뜨리면 API가 404를 반환한다.**
(권한 없음이 아니라 "존재하지 않음"으로 응답하므로 디버깅 때 헷갈리기 쉽다.)

### 3. DB ID 확보

DB를 전체 페이지로 열었을 때의 URL:

```
https://app.notion.com/p/<32자리 DB ID>?v=<32자리 뷰 ID>
                          ^^^^^^^^^^^^^^^ 이 부분
```

`?v=` 앞의 32자리가 DB ID다. 뒤에 오는 뷰 ID도 길이가 같고 **앞부분 몇 글자까지
똑같이 생겼다** — 노션 ID가 시간순으로 생성되기 때문이다. 헷갈리지 않도록 주의.

DB가 페이지 안에 인라인으로 박혀 있으면 URL에 DB ID가 아니라 *페이지* ID가 나온다.
DB 블록의 `⋮⋮` → **전체 페이지로 열기** 후 주소창을 복사할 것.

### 4. API 버전과 데이터 소스 (중요)

**`2025-09-03` 버전부터 데이터 모델이 바뀌었다.** 노션의 "데이터베이스"는 이제
여러 개의 **데이터 소스(data source)**를 담는 *컨테이너*이고, 실제 행(row)은
데이터 소스에 들어 있다.

그래서 조회 엔드포인트가 바뀌었다:

```
구  POST /v1/databases/<DB_ID>/query        ← 더 이상 쓰지 않음
신  GET  /v1/databases/<DB_ID>              → data_sources[] 획득
    POST /v1/data_sources/<DS_ID>/query     → 실제 행 조회
```

즉 **DB ID만으로는 행을 못 읽고, 데이터 소스 ID를 한 번 알아내는 단계가 필요하다.**
데이터 소스 ID는 DB를 지우지 않는 한 바뀌지 않으므로 `.env`에 캐싱해 매 요청의
왕복을 없앤다. (없으면 런타임에 조회해서 채우는 fallback을 둔다)

이 프로젝트는 `Notion-Version: 2026-03-11`(현재 최신)을 쓴다.

> 구버전 `2022-06-28`도 당분간 동작하지만, 데이터 소스가 하나인 DB에 한해서다.
> 새로 만드는 코드가 굳이 폐기 예정 경로를 탈 이유는 없다.

### 5. 환경변수

`.env` (git 제외 확인 완료 — `.gitignore:34`)

```sh
NOTION_TOKEN=ntn_xxxxxxxxxxxxxxxxxxxx
NOTION_GUIDE_DB_ID=3b08b57d7cf480f0a091ec50c12108a3
NOTION_GUIDE_DS_ID=<점검 스크립트가 알려주는 값>
```

`NEXT_PUBLIC_` 접두사를 **붙이지 않는다.** 토큰과 프록시 로직은 서버에만 있어야 한다.
Vercel 배포 시 Project Settings → Environment Variables에도 동일하게 등록한다.

## 캐싱 정책

| 대상 | 설정 | 근거 |
|---|---|---|
| 가이드 페이지 (ISR) | `revalidate = 300` | 기존 가이드 페이지와 동일. JSON만 오가므로 저렴 |
| 이미지 프록시 응답 | `max-age=31536000, immutable` | `v` 토큰이 있어 내용이 바뀌면 URL이 바뀜 |
| `next/image` | `minimumCacheTTL` 상향 | 기본 14400초(4시간)면 원본을 하루 6번 재조회 |

`next.config.ts`에는 remote hostname을 추가할 필요가 없다.
이미지가 `/api/guide-image`라는 **동일 출처 경로**로 서빙되기 때문이다.
