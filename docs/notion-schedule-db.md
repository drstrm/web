# 일정 노션 DB 스키마 (개발자용)

홈 **캘린더**, 홈 **To Do List**, 투표 원클릭의 **앱 투표 버튼**이 함께 쓰는 DB.
연결(Connection) 만들기 · 토큰 발급 · 데이터 소스 개념은
[notion-guide-db.md](./notion-guide-db.md)의 「노션 셋업 절차」와 동일하므로 여기서는
일정 DB에만 해당하는 내용을 적는다.

- DB URL: `https://app.notion.com/p/3ccdec8e2bf08082806ffbaa8282e411?v=…`
  (「schedules」 **인라인 DB**)
- 코드: `lib/notion.ts`의 `getSchedules()` → `lib/content.ts`의
  `getCalendarEvents()` · `getTodoList()` · `getActiveVotes()`
  → `app/page.tsx` · `app/api/votes/route.ts`

세 화면이 **한 DB**를 `노출 위치` 열로 나눠 쓴다. 셋 다 같은 컴백 일정을 각자 다르게
보여줄 뿐이라, DB를 나누면 운영진이 같은 일정을 세 번 적게 된다. 투표 기간을 한 줄
적으면 달력에 기간이 깔리고, 할일 목록에 뜨고, 투표 버튼이 켜진다.

> 예전에는 Supabase `schedules` 테이블이 이 역할을 했다. 옮기면서 `published` ·
> `all_day` · `sort_order` 열은 없앴다 — 아래 각 항목에 대응하는 방법을 적어 두었다.

## DB 속성 정의

| 속성명 | 타입 | 필수 | 용도 |
|---|---|---|---|
| `이름` | 제목(Title) | ✔ | 달력 · 할일 · 투표 버튼에 표시되는 일정 이름 |
| `노출 위치` | 다중 선택 | ✔ | `calendar` · `todo` · `vote` — 어느 화면에 나갈지 |
| `기간` | 날짜(Date) | | 시작 · 종료. 비우면 기한 없는 상시 할일 |
| `종류` | 선택 | | 기본 이모지가 여기서 갈린다 (아래 표) |
| `플랫폼` | 다중 선택 | | 아이콘 (`public/icons/<key>.png`). 이모지 대신 표시 |
| `매년 반복 여부` | 체크박스 | | 데뷔일 · 생일처럼 매년 같은 날 돌아오는 일정 |
| `매일 반복 여부` | 체크박스 | | 기간 내내 매일 해야 하는 할일 |
| `url` | 텍스트 / URL | | 눌렀을 때 가는 곳 (투표 링크 · 스밍 링크) |
| `guide_url` | 텍스트 / URL | | 할일 오른쪽 「가이드」 버튼이 가는 곳 |
| `설명` | 텍스트 | | (선택 열) 할일 이름 아래 한 줄 |
| `emoji` | 텍스트 | | (선택 열) `종류` 기본 이모지를 덮어쓴다 |
| `순서` | 숫자 | | (선택 열) 할일 목록에 나오는 차례. 작은 수가 앞 |

`이름`이 비었거나 `노출 위치`를 하나도 안 고른 행은 어느 화면에도 나오지 않는다
(노션이 기본으로 만들어 두는 빈 행이 여기서 함께 걸러진다). 바꿔 말해 **행을 지우지
않고 `노출 위치`만 비우면 임시로 내릴 수 있다** — 예전 `published` 열이 하던 일이다.

「(선택 열)」로 적힌 셋은 **없어도 동작한다.** 없으면 각각 설명 없음 · `종류` 기본
이모지 · 만든 순서로 떨어진다. 만들고 지우는 데 코드 수정이 필요 없다.

### `노출 위치`

| 값 | 나가는 곳 | 그 화면이 요구하는 것 |
|---|---|---|
| `calendar` | 홈 캘린더 | `기간`이 있어야 한다 (날짜가 없으면 달력에 놓을 자리가 없다) |
| `todo` | 홈 To Do List | 지금이 `기간` 안이어야 한다. 기간이 비면 항상 표시 |
| `vote` | 투표 원클릭의 앱 버튼 | `기간`(시작·종료 모두) · `url` · `플랫폼`이 다 있어야 버튼이 켜진다 |

여러 개를 함께 고를 수 있다. 실제로 투표 일정은 보통 `todo` + `vote`, 컴백 기간은
`calendar` + `todo` 를 함께 고른다.

`vote` 는 `플랫폼` 값이 투표 앱 버튼(`lib/oneclick.ts`의 `VOTE_APPS`)의 key와
같아야 짝이 맞는다 — `coogoong` · `mnetplus` · `mubeat` · `muniverse` · `linc` ·
`higher`. 같은 앱에 여러 건이 걸리면 **마감이 빠른 건**이 버튼에 뜬다.

### `기간` — 시각을 적느냐가 동작을 가른다

노션 날짜 칸의 「시간 포함」 스위치 하나가 예전 `all_day` 열을 대신한다.

| 적는 법 | 화면 | To Do 마감 판정 |
|---|---|---|
| 날짜만 (`8월 27일`) | 「하루 종일」로 본다. 마감 표시에서 시각을 뗀다 | **종료일 그 날 끝까지** (다음 날 0시에 사라진다) |
| 시각까지 (`8월 27일 오후 7:00`) | `09.06 19:00` 처럼 시각까지 표시 | 적은 그 시각에 사라진다 |
| 통째로 비움 | 달력에는 안 나온다. 할일에는 항상 남는다 | 안 끝난다 |
| 종료만 비움 | 하루짜리 일정 | 안 끝난다 |

**종료일은 그 날을 포함한다.** `8/1 → 8/7` 로 적으면 8월 7일 하루까지 살아 있다가
8월 8일 0시(KST)에 사라진다. 값을 그대로 읽으면 8/7 00:00 이 되어 하루 일찍
사라지므로, 코드가 하루 종일 일정의 종료일에만 하루를 더해 준다
(`lib/notion.ts`의 `parsePeriod()`).

시간대는 노션 워크스페이스 설정을 따르고, 화면 표기는 전부 KST로 변환된다
(`lib/datetime.ts`). 날짜만 적은 값은 **KST 자정**으로 읽는다 — 서버가 UTC로 돌아도
결과가 같아야 하기 때문이다.

### `매년 반복 여부` · `매일 반복 여부`

| 열 | 켜면 |
|---|---|
| `매년 반복 여부` | 달력이 연도를 무시하고 **월-일만** 본다. 생일 · 데뷔일용 |
| `매일 반복 여부` | To Do 마감 자리에 날짜 대신 **「매일」**이 뜬다 |

`매년 반복 여부`를 켠 일정은 적어 둔 연도가 몇 년이든 매년 그 날짜에 나온다
(2월 29일처럼 그 달에 없는 날짜는 건너뛴다).

`매일 반복 여부`는 「오늘 해도 내일 또 해야 하는 일」 표시일 뿐, 기간 판정은 바꾸지
않는다. 기간을 함께 적으면 그 기간 내내 매일 뜨고, 비워 두면 계속 뜬다.

### `종류` — 기본 이모지

`플랫폼`에 아이콘이 있으면 아이콘이 이기고, 없으면 이 이모지가 나온다.
`emoji` 열을 만들어 값을 적으면 그쪽이 가장 세다. 목록은 `lib/kind-emoji.ts`.

| 값 | 이모지 | | 값 | 이모지 |
|---|---|---|---|---|
| `debut` | 💚 | | `chart` | 📊 |
| `birthday` | 🎂 | | `broadcast` | 📺 |
| `comeback` | 💿 | | `streaming` | 🎧 |
| `vote` | 🗳️ | | `etc` | 📌 |

여기 없는 값을 적거나 비워 두면 `etc`(📌)로 본다.

### `플랫폼` — 아이콘

`public/icons/<key>.png` 의 파일명을 그대로 적는다(`mnetplus` · `melon` · …).
목록은 `lib/platform-icons.ts`. 표시명(`엠넷플러스`)으로 적어도 받아 준다 — 가이드
DB가 그렇게 쓰고 있어서 둘 다 통과시킨다. 여러 개를 고르면 **첫 번째**만 쓴다.

### `url` · `guide_url` — 사이트 안 · 밖을 자동으로 가른다

판단은 사이트 공용 규칙(`lib/url.ts`의 `resolveHref()`)이 하고, 렌더링은
`<SmartLink>`가 한다. `https://` 를 빠뜨려도, 내부 경로(`/guide/voting`)를 적어도
알아서 처리한다 — 표는 [notion-links-db.md](./notion-links-db.md) 참고.

## 순서

To Do 목록은 **`순서` 숫자 열 → 마감 임박 순**으로 나온다. `순서` 열이 없거나 값이
전부 비어 있으면(지금이 그렇다) 사실상 **마감 임박 순**이다 — 오늘 안에 해야 하는
일이 위로 올라오고, 기한 없는 상시 할일이 맨 아래로 간다.

즉 `순서` 열은 「이건 무조건 맨 위」처럼 마감과 무관하게 고정하고 싶을 때만 만들면
된다. 값을 적은 행끼리는 그 숫자대로, 안 적은 행은 뒤에서 마감 임박 순으로 붙는다.

달력은 날짜순, 투표 버튼은 마감이 빠른 순이라 `순서` 열의 영향을 받지 않는다.

> **노션에서 줄을 드래그해도 사이트 순서는 바뀌지 않는다.** 이유는
> [notion-links-db.md](./notion-links-db.md)「순서」의 설명과 같다.

점검은 `node scripts/notion-check.mjs`.

## 반영 주기

| 화면 | 늦어도 언제 반영되나 |
|---|---|
| 홈 캘린더 · To Do | **5분** (`app/page.tsx`의 `revalidate = 300`) |
| 투표 앱 버튼 | **1분** (`getSchedules()`의 fetch 캐시 60초 + 버튼이 1분마다 재조회) |

「지금 진행중인가」는 노션이 아니라 **화면을 그리는 시점에** 계산한다. 노션에는
PostgREST 의 `now` 같은 리터럴이 없어서, 조회에 현재 시각을 박으면 Next 의 fetch
캐시가 매번 빗나가기 때문이다. 그래서 행은 전부 받아 두고 시각 판단만 렌더 때 한다
(`lib/notion.ts`의 `getSchedules()` 주석).

결과적으로 **마감 직후 최대 5분간은 끝난 할일이 홈에 남아 보인다.** 투표 버튼은
전용 라우트(`/api/votes`)를 거치므로 1분이다. 더 정확히 맞춰야 하면 홈의
`revalidate` 를 낮추거나 `TodoList` 를 클라이언트 컴포넌트로 돌려 브라우저 시각으로
한 번 더 거르면 된다.

## 환경변수

```sh
NOTION_TOKEN=ntn_xxxxxxxxxxxxxxxxxxxx        # 다른 노션 DB 와 같은 토큰
NOTION_SCHEDULE_DB_ID=3ccdec8e2bf08082806ffbaa8282e411
NOTION_SCHEDULE_DS_ID=3ccdec8e-2bf0-8041-87b3-000b46ee6472   # 선택: 요청당 왕복 한 번을 아낀다
```

이 DB는 인라인이므로 연결(Connection)은 **DB 자신 또는 DB가 들어 있는 페이지**에
붙인다.

연결을 빠뜨리면 API가 404를 반환하고 **캘린더 · To Do 가 빈 상태로**, 투표 버튼은
**「진행중 투표 없음」**(기본 링크)으로 떨어진다. 페이지가 500이 되지는 않는다
(서버 로그에 `[schedules] 노션 조회 실패` 가 찍힌다).
